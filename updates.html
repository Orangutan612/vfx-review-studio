本次 · v1.4.11

评分可审计 + 不许臆断
  • 分数不再由模型"感觉"给上一版给了评分锚点，实测还是压分（模型可以一边写"只有两三条可改"、一边给 5 分）。现在总分改成由它自己的 pass / warn / fail 结论推导（通过 10 · 有隐患 6.5 · 不通过 2.5，看不清不计入），并在报告里写出判定依据：「x 项通过 · y 项有隐患 · z 项不通过」。判定有异议，就去看那几条结论 —— 分数从黑箱数字变成可追查的结果。
  • 明令禁止臆断（硬要求）每条结论和每条建议都必须绑定画面证据（时刻 + 部位 + 现象）或实算数值（亮度 / mo 的具体数字）；禁止"我觉得 / 应该是 / 大概作者想 / 风格问题"这类没有依据的说法；拿不准的写进"证据边界"。看不到引擎参数、帧率、制作过程，就不许推测。
  • 参考区间可以马上看效果「用这一段」旁边多了「读取这一段」—— 立即按你选的区间解码一次并预览，先确认抽出来的是你要那一下，再开始评审。

上一版 · v1.4.9

本次 · v1.4.9

修时长误判 + 参考放宽
  • 修：29 秒的视频被说成"超过 2 分钟"、80 秒的参考被说成"太短"同一个原因：有些导出软件把 MP4 里 mdhd.duration 写成 0，而程序只看了这一个字段，于是时长算成 0 或被除小。两个方向相反的报错，其实是同一处读错数。现在按可信度取第一个合理的值：mvhd → tkhd → mdhd；主视频再用浏览器解出的时长兜底交叉验证。
  • 参考片段上限 30 → 120 秒以前参考视频最多取前 30 秒，长镜头（比如一个大招 80 秒）只能看到开头。现在和作品一样放到 2 分钟。

上一版 · v1.4.8

本次 · v1.4.8

评分有了尺子
  • 修：分数没有统一的尺子以前提示词里对评分只有一句"各给 0–10 分、不要一律给中间分糊弄"，没有定义"几分算好"。模型只好自己立一把 —— 而大模型天然拿"电影级 / 3A"当满分基准，于是像样的练习作品也会被压到 5 分上下、总分 50 出头。现在明确写出锚点：9–10 商业上线水准 · 7–8 专业可用 · 5–6 合格偏上 · 3–4 问题明显 · 0–2 基本没成立；并写死基准：没给参考时，以「同类个人练习 / 独立项目的良好水平」为 6–7 分中位，不许拿 3A 当满分基准；分数还必须和你写出的建议一致（通篇只说得出两三条可改的地方，就不该给 5 分）。
  • 分数旁边直接写出"什么水平"报告里那个数字不再是孤零零的 51 分 —— 现在会带上档位（商业上线水准 / 专业可用 / 合格偏上 / 问题明显 / 基本没成立），而且档位文字和颜色用的是同一套阈值（90 / 70 / 50 / 30）（以前颜色阈值是 85/70/55，和文字标签对不上，自己打架）。

上一版 · v1.4.7

本次 · v1.4.7

修换片子报错 + 删除按钮
  • 修：换个视频就报「支持最长 2 分钟」不是新旧视频时长相加 —— 是读时长的办法不可靠：容器里有两个 timescale（movie / media），不同软件导出的片子这两个值经常不一致，一除就差几十倍，30 秒被算成几十分钟。现在以浏览器自己解出的时长为准，容器值只在读不到时兜底，这类文件从此不会误判。
  • 作品区加了「删除」按钮（新）选错了或不想评了，点一下就把视频移掉，退回"还没选作品"的样子（同时释放掉本地视频占的内存）。「换一个视频」旁边就是它。

上一版 · 1.4.v1.4.5

本次 · v1.4.5

选区自由 + 代价可见
  • 修：选区放开了，跑起来还是被拦上一版只改了界面校验，但解码器里还藏着一道 15 秒的硬闸 —— 界面让你选 30 秒，一点开始评审就报「评审范围最长 15 秒」。这次两处一起改，并加了一条自检专门盯解码器，防止再出现"只改一处"。
  • 档位做成看得见的标签以前代价只是提示里的一串字，容易看漏。现在选区旁边直接挂一个彩色标签：省 / 标准 / 偏高 / 很重，后面跟着页数（如「标准 · 38 页」）。
  • 小按钮不再像链接「换一个视频」「恢复整段」原来带虚线下划线，现在是有边框的按钮。
  • 选区不再限长原来是 15 秒的死上限（一段完整的爆炸或技能演出经常要切成两半）。现在不设人为上限 —— 能选多长由视频本身决定（上传上限 2 分钟），整段丢进去评也行。
  • 代价实时算给你看（新）选区越长、模型要读的接触表页数越多，耗时和费用就越高 —— 这是事实，与其一刀切替你决定，不如标清楚让你自己权衡。拖动选区时下面实时显示：约多少帧 / 多少页接触表 / 属于哪一档 —— 省（≤15 秒，约 19 页内）· 标准（≤30 秒，约 38 页）· 偏高（≤60 秒，约 75 页）· 很重（整片级别，上百页）。

v1.4.0

换渲染内核
  • 接上 GPU 渲染（WebGL2 片元着色器）把渲染从 CPU 搬到 GPU（WebGL2 片元着色器）。一个 512² 图层从 25–80ms 降到 4ms —— 拖滑杆不再卡顿，这才是"顺手"的关键。拖滑杆不再卡顿。这一版最终把 54 个生成器全部搬上了 GPU（见下方）。
  • 修掉一批贴图的问题逐个看过去，抓出并修掉：边缘被切平（14 个"画面里放元素"的类型现在会在贴边前淡出，融球/散景/神光不再糊在边上）、散景光斑跑到框外的放置 bug、多边形/星形/十字/月牙的纯白硬边剪贴画感（加了内部明暗，有体积了）、融球和散景默认太大糊成一坨。
  • 用 SDF 图元重做 6 个最难看的（GPU）建了一套 GLSL 图元库（cov 抗锯齿、smin 平滑并集、sdSeg 线段距离、gauss），并用它重写了融球 / 散景 / 火花 / 细胞 / 十字 / 月牙 —— 融球现在是独立柔边球体、散景是有边框的圆盘、火花是带拖尾的胶囊、细胞有明暗分块。GPU 类型从 8 个增到 14 个。
  • 第二批 6 个也重做了（GPU）神光（从画面上方洒下的宽柔光柱）· 矩阵（真正下落的数字雨，带拖尾和亮头）· 水晶（有棱面明暗的晶格）· 编织（一横一竖交织的线）· 马赛克（带斜边和间隙的砖块）· 做旧（多层污渍而不是细麻点）。GPU 类型 14 → 20 个。
  • 归属声明写清楚 + 仓库简介改准内嵌来源补上国内可直连的「贴图工坊」(vfxmento.xyz)，并在 README 里写明：两个页面都只是 iframe 引用原站，代码与内容属于原作者，本站不复制、不改写、不再分发，原作者要求即可移除。另外 GitHub 仓库简介原写「自带 API Key」容易被误解成"点进网页就有 key 用"，已改成「用你自己的模型 API Key，站点不提供」。
  • 贴图工具页只保留一个来源一度加过国内可直连的「贴图工坊」(vfxmento.xyz)，但实测它拒绝被内嵌（iframe 里显示「拒绝连接」，站点本身是活的，是不允许被别的网页嵌）。既然用不了就下掉了，README 与说明里也一并删掉。现在只保留 gameanimation 的 TextureCreate，并把「拒绝连接」的成因写进了兜底提示。
  • 修：缩略图和实际预览「不是一张脸」根因有两条：① 左栏缩略图走的是 CPU 函数，舞台走的是 GPU 着色器，两条路算的不是一个东西；② 我 GLSL 里的哈希是自己写的浮点版，和 CPU 那套 32 位整数位运算哈希结构不同，所以 GPU 出来的噪波偏"糊"。现在缩略图和舞台走同一条渲染路径，并且把 CPU 的哈希/梯度表逐位等价地移植进着色器——
  • 54 个生成器全部上了 GPU把剩下 30 个（噪波族 / 图案族 / 自然现象族）一次性全搬到片元着色器，现在每一个类型都跑 GPU，拖滑杆基本不掉帧。做法是把它们的参数和算法逐个对照着转 —— 不是重画，是同一套数学换到 GPU 上算。
  • 第三批 4 个也重做了（GPU）闪电（真正的分叉雷，线段距离场 + 辉光，不再是抖动的曲线）· 溶解（有序抖动 + 噪声，边缘带亮边）· 能量场（加强，不再发灰）· 等离子（加了域扭曲，不再退化成同心圆）。GPU 类型 20 → 24 个。
