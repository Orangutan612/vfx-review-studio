评分可审计 + 不许臆断
  • 分数不再由模型"感觉"给上一版给了评分锚点，实测还是压分（模型可以一边写"只有两三条可改"、一边给 5 分）。现在总分改成由它自己的 pass / warn / fail 结论推导（通过 10 · 有隐患 6.5 · 不通过 2.5，看不清不计入），并在报告里写出判定依据：「x 项通过 · y 项有隐患 · z 项不通过」。判定有异议，就去看那几条结论 —— 分数从黑箱数字变成可追查的结果。

上一版 · v1.4.9

本次 · v1.4.9

修时长误判 + 参考放宽
  • 修：29 秒的视频被说成"超过 2 分钟"、80 秒的参考被说成"太短"同一个原因：有些导出软件把 MP4 里 mdhd.duration 写成 0，而程序只看了这一个字段，于是时长算成 0 或被除小。两个方向相反的报错，其实是同一处读错数。现在按可信度取第一个合理的值：mvhd → tkhd → mdhd；主视频再用浏览器解出的时长兜底交叉验证。
  • 参考片段上限 30 → 120 秒以前参考视频最多取前 30 秒，长镜头（比如一个大招 80 秒）只能看到开头。现在和作品一样放到 2 分钟。

修换片子报错 + 删除按钮
  • 修：换个视频就报「支持最长 2 分钟」不是新旧视频时长相加 —— 是读时长的办法不可靠：容器里有两个 timescale（movie / media），不同软件导出的片子这两个值经常不一致，一除就差几十倍，30 秒被算成几十分钟。现在以浏览器自己解出的时长为准，容器值只在读不到时兜底，这类文件从此不会误判。

  • 修：缩略图和实际预览「不是一张脸」根因有两条：① 左栏缩略图走的是 CPU 函数，舞台走的是 GPU 着色器，两条路算的不是一个东西；② 我 GLSL 里的哈希是自己写的浮点版，和 CPU 那套 32 位整数位运算哈希结构不同，所以 GPU 出来的噪波偏"糊"。现在缩略图和舞台走同一条渲染路径，并且把 CPU 的哈希/梯度表逐位等价地移植进着色器——
  • 54 个生成器全部上了 GPU把剩下 30 个（噪波族 / 图案族 / 自然现象族）一次性全搬到片元着色器，现在每一个类型都跑 GPU，拖滑杆基本不掉帧。做法是把它们的参数和算法逐个对照着转 —— 不是重画，是同一套数学换到 GPU 上算。
  • 第三批 4 个也重做了（GPU）闪电（真正的分叉雷，线段距离场 + 辉光，不再是抖动的曲线）· 溶解（有序抖动 + 噪声，边缘带亮边）· 能量场（加强，不再发灰）· 等离子（加了域扭曲，不再退化成同心圆）。GPU 类型 20 → 24 个。

还没做 / 已知取舍

  • 动画导出走「序列帧」不走 GIFGIF 只有 1 位透明和 256 色，喂引擎不够用；所以做的是序列帧（编号 PNG 打包 zip）和序列图集。需要 GIF 的话，用序列帧在 AE / PS 里转一下就有一份质量更好的。
  • 模型服务商的 CORS 差异链接版由浏览器直连模型服务，所以对方必须放行跨域。实测可用：DeepSeek / 通义百炼 / 智谱 / 火山方舟。
  • github.io 在国内访问不稳定这是托管位置的固有限制，不是代码问题。本地版可以当兜底。
